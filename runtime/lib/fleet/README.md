Map of the fleet's domains and their layered topology. **This file is a map, not a
contract**: each domain owns its contract in its facade `@moduledoc` (`h Fleet.<Dom>`)
and its own `lib/fleet/<dom>/README.md` card. The cross-cutting reading path is
`CLAUDE.md` (build/run/invariants) and `Fleet.Pilot`'s moduledoc (the 5-phase story).

The dependency structure is declared in each facade's `use Boundary` and enforced at
compile time — the single source of truth. The table below is a generated projection.

## Reading the table

- **foundation** (`deps: []`) — pure vocabulary/validation utilities, no process, no I/O
  authority. The one mechanically checkable layer name.
- A domain only ever calls DOWNWARD (boundary compiles this); the few deliberate upward
  edges are runtime seams, config-injected and documented in `CLAUDE.md` — never
  compile-time deps.
- Layer names other than `foundation` are an editorial reading declared in ONE place
  (`@layers` in `lib/mix/tasks/lcars.topology.ex`); a new or moved domain fails the gate
  until its layer is consciously (re)declared.
